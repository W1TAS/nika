# Животный мир для NIKA

Фрагмент базы знаний и локальный классификатор для лабораторных работ № 1, № 2 и № 3. Пользователь задаёт вопрос о животном, классификатор определяет тему вопроса и животное, а NIKA находит соответствующий факт в базе знаний и формирует ответ по шаблону.

## Что сделано в лабораторных работах

| Работа | Что сделано | Основные файлы |
| --- | --- | --- |
| ЛР1 — предметная область «Животный мир» | В SCS описаны классы животных, понятия и отношения, а также экземпляры и факты о них. Эти данные составляют основу базы знаний, к которой обращаются правила ЛР3. | `section_subject_domain_of_animal_world.scs`, `concepts/*.scs`, `concepts/instances/*.scs`, `relations/*.scs` |
| ЛР2 — классификация сообщений | Описаны классы вопросов, роль сущности `rrel_entity`, сценарий диалога, замена Wit.ai локальным Python-классификатором и проверки распознавания. Оставлены места для скриншотов кода, терминала и диалога NIKA. | `scenario_engine.py`, `scenario_server.py`, `messages/messages.scs`, `classification/animal_world.zip` |
| ЛР3 — логические правила и фразы | Описаны условия срабатывания правил, получение фактов из базы знаний, шесть тематических правил и двенадцать фраз-шаблонов (по две на класс). Приведены вопросы для проверки каждого правила и места для скриншотов ответов NIKA. | `rules/lr_message_about_*.gwf`, `phrases/concept_phrase_about_*.gwf`, факты в `concepts/instances/*.scs` |

Отчёты по ЛР2 и ЛР3 сохранены отдельно как `Отчет_ЛР2_Классификатор_сообщений.docx` и `Отчет_ЛР3_Логические_правила_и_фразы.docx`. Поля для скриншотов в них нужно заполнить фактическими снимками своей запущенной NIKA.

## Как получается ответ

1. NIKA отправляет текст вопроса локальному серверу по адресу `/message`.
2. `scenario_server.py` вызывает `scenario_engine.py`. Движок выбирает **intent** — тему вопроса — и находит **entity** — названное животное. Например, для «Где обитает зубр?» это `about_habitat` и `зубр`.
3. Сервер возвращает NIKA JSON с intent и сущностью под ролью `rrel_entity`. Русское имя сущности передаётся в поле `value`, чтобы NIKA могла сопоставить его с `nrel_main_idtf` в базе знаний.
4. Класс сообщения, описанный в `messages/messages.scs`, и сущность попадают в SC-память. Загруженное из GWF правило проверяет класс сообщения и наличие нужного отношения у животного. Для вопроса о месте обитания это `nrel_habitat`.
5. Правило создаёт ответное сообщение, а фраза из `phrases/*.gwf` подставляет имя животного и найденное значение. NIKA показывает результат пользователю.

Файлы GWF загружаются в базу знаний при её сборке. При каждом вопросе NIKA работает с уже загруженными SC-структурами, а не открывает GWF-файл по имени.

`scenario_engine.py` также формирует текст ответа для локальной проверки. Поле `nika_reply`, которое сервер может добавить в JSON, служит только для отладки: ответ в интерфейсе NIKA формируют её правила и фразы.

## Какие вопросы поддерживаются

Подставляйте вместо животного имя экземпляра из базы знаний. Формулировки ниже соответствуют текущим шаблонам Python-классификатора и тематическим правилам.

| Тема (`intent`) | Пример вопроса | Откуда берётся ответ |
| --- | --- | --- |
| Описание (`about_entity`) | Что такое зубр? | Описание сущности (`nrel_note`); класс `about_entity` уже предусмотрен в NIKA. |
| Местообитание (`about_habitat`) | Где обитает лев? / Где живёт волк? | `nrel_habitat` |
| Питание (`about_food`) | Чем питается волк? / Что ест беркут? | `nrel_food_type` |
| Охранный статус (`about_conservation`) | Какой охранный статус у зубра? | `nrel_species` → `nrel_conservation_status` |
| Научное название (`about_scientific_name`) | Как по-научному называется волк? | `nrel_scientific_name` |
| Поведение (`about_behaviour`) | Как ведёт себя волк? | `nrel_behaviour` |
| Размножение (`about_reproduction`) | Как размножается волк? | `nrel_reproduction_type` |


Ответ зависит от наличия соответствующего факта в базе знаний и от формулировки вопроса. Классификатор использует явно заданные регулярные выражения, а не обученную языковую модель. Если сущность или нужное свойство не найдены, сервер оставляет сообщение без тематического intent, чтобы NIKA могла использовать стандартный ответ для неподходящего запроса.

## Состав фрагмента базы знаний

| Путь внутри `section_subject_domain_of_animal_world` | Назначение |
| --- | --- |
| `concepts/instances/*.scs` | Животные, виды, местообитания и другие экземпляры со связями и русскими именами. |
| `concepts/*.scs`, `relations/*.scs` | Понятия предметной области и отношения между ними. |
| `messages/messages.scs` | SC-классы сообщений и их идентификаторы intent. |
| `rules/*.gwf` | Шесть тематических логических правил для ответа. |
| `phrases/*.gwf` | Двенадцать фраз-шаблонов: по две на каждую тему. |
| `classification/animal_world.zip` | Сохранённый экспорт классификационных данных ЛР2. При локальном запуске запросы обрабатывает Python-классификатор. |

## Размещение и запуск

1. Поместите папку `section_subject_domain_of_animal_world` в `kb/extra/` проекта NIKA.
2. Поместите `scenario_engine.py` и `scenario_server.py` рядом друг с другом в `tools/` проекта. Сервер импортирует движок как модуль `scenario_engine`.
3. Из корня проекта проверьте классификацию одного вопроса:

   ```bash
   python tools/scenario_engine.py --root . --ask "Где обитает зубр?"
   ```

4. Запустите локальный сервер:

   ```bash
   python tools/scenario_server.py --root .
   ```

5. Укажите адрес сервера в `nika/nika.ini`:

   ```ini
   [wit-ai]
   server_token = local
   url = http://127.0.0.1:8080/message
   ```

6. Соберите базу знаний и запустите NIKA способом, предусмотренным используемой версией проекта. Затем задайте вопросы из таблицы выше в интерфейсе.

Адрес `127.0.0.1` подходит, когда NIKA видит сервер на том же сетевом узле. Если компоненты запущены в разных контейнерах, укажите в `url` доступный NIKA адрес сервера.
